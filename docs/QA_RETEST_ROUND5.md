### 0.1 测试数据从哪来

**来源一（推荐）：直接导出库里已有的书。** 本实例里已有若干真实资料（QA 前几轮报告里出现过这些）：
`27王道《数据结构》`、`27王道《操作系统》`、`考研英语—2026年真题`、`1000题`、`26张宇基础30讲（高数）_含目录.pdf`
→ 随便挑一本 → 资料详情页「**导出书本包**」，**勾上「带上原文件」**（包里会带上原 PDF，体积大，正好用来看上传百分比）。

**来源二：测试期间上传的资料**（例如 26张宇那份 PDF），同样可以导出成本书包。

**来源三：从零造（不建议，慢）** —— 上传任意一个小 PDF/markdown → 出题 → 导出书本包。

> ⚠️ 导出后**必须改一个字节再重打包**，否则重导必然撞内容去重：
> ① 解压 zip → 编辑 `pages/page_001.md`，末尾加一行 `QA 测试 1016`
> ② 重新压缩成 zip（顶层有没有目录都行，导入会自动剥掉）
> ③ 用它做导入用例；**再另存一份没改过的原样 zip**，专用于「重复导入」用例
> （导入按整本书正文的 sha256 去重，原样重导一定提示"已导入过"）

**副作用与清理**：导入会在库里**多出一本书**（内含题目也会进题库）。建议：
- 导入前先建一个测试资料组（如 `QA测试组_1016`）并把包导进去；
- 测完把这本书**删掉**（删除资料会连带清理它的题目引用），测试组一并删。

**C 组（扫描件）的前置**：`/doc-parse` 的 preview 需要本机 **MinerU 可用**。若未安装/未就绪：
- 该用例会**快速失败**（而不是长时间占用），此时 **C1 记为 ➖ 不作为**，改用 **C2「连传 4 个 PDF」** 来验"长活不卡全站"；
- 或先在设置页把 MinerU 装好再测。

## A. 上传页四个方式（本轮把「导入书本包」并成了第 4 个方式）

判定口径：四个方式**行为一致** —— 点卡片 = **选中**（下面拖拽区跟着变），再在拖拽区**选文件**；不应该再出现"点一下直接弹文件框"。

| 编号 | 级别 | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| A1 | P0 | 390 宽打开 `/knowledge/upload` | 一排**四个**卡片：上传文档 / 图片 OCR / 拍照识别 / **导入书本包** | |
| A2 | P0 | 逐个点击四个卡片 | 每次只是**切换选中高亮**，**不弹**任何文件选择框 | |
| A3 | P0 | 选中「上传文档」→ 拖入一个 PDF | 走原上传链路：任务列表出现、状态推进到完成 | |
| A4 | P0 | 选中「图片 OCR」→ 选一张图片 | 同上；文件选择框应只收图片（`accept` 生效） | |
| A5 | P0 | 切换四个卡片 | 拖拽区**图标与文案跟着变**（zip 模式换成"分页 + 图片 + 题库"的说明） | |
| A6 | P0 | 切到「导入书本包」看下方 | **「强制 OCR」选项应隐藏**；切回其它方式后**应重新出现** | |
| A7 | P1 | 选「图片 OCR」后点拖拽区 | 弹出的是文件选择框（`accept` 为图片），**不是** zip | |
| A8 | P1 | 拖拽区在忙碌时再点 | 不应重复触发（忙碌态点它没反应） | |

> A3/A4 是"原有三个方式没被我改坏"的回归项，**必测**。

## B. 导入书本包：两段进度 + 作业接口

前端应该能区分**「还在上传」**和**「已进入处理」**：
- 上传阶段看 **XHR 上传百分比**（前端算的，后端不参与）；
- 处理阶段看**作业**：`GET /api/v1/jobs/{job_id}` 里的 `status / message / progress / result`。

| 编号 | 级别 | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| B1 | P0 | 用 0.1 的包（**带原文件**，较大）导入 | 拖拽区先显示「**上传中 x%**」且百分比**会增长**；上传完成后立刻切成处理阶段文案 | |
| B2 | P0 | 继续看处理阶段文案 | 依次经过：排队中… → **解包中… → 写入资料… → 保存图片… → 分段中… → 向量化中… → 写入题库…**（不完全出现也算通过，但至少能看到 2 段以上） | |
| B3 | P0 | 完成后看结果与资料列表 | 提示"书本导入成功（N 页，含 X 题…）"；资料页出现该书，可打开、可刷题 | |
| B4 | P0 | **长活不阻塞（本轮最重要）**：在大包导入进行中，另开一个标签/窗口访问 `/`、`/quiz`、`/chat` | **全部正常秒开**，不出现 502 / 一直转圈 / 502 Bad Gateway | |
| B5 | P1 | 导入进行中调 `GET /api/v1/jobs?active=1` | 能查到该作业（`kind=import_package`、`status=running`、`message` 是当前阶段）；列表页看不到"完成"的历史作业超过 30 分钟 | |
| B6 | P0 | 把**同一个 zip 再导一次** | 提示「已导入过，跳过」，**不新增**资料；作业 `status=failed` 且原因含「已上传过」 | |
| B7 | P1 | 导一个**坏 zip**（随便一个文本文件改名 `.zip`） | 有可读错误提示，**不卡死**、不出现无限转圈；作业标记 failed | |
| B8 | P1 | 导入一定时间后再刷新页面 | 资料页能看到该书（前台刷新不影响后台作业）；未完成的作业不会让页面报错 | |

**导入类问题必须附**：`job_id` + `GET /api/v1/jobs/{job_id}` 的**返回原文**（现在有作业号了，这一条能直接定位）。
