# 知拾（托管版）产品设计

> **定位**：面向正式上线、多用户、由知拾提供服务的产品规格。  
> **不是**：开源实验仓库的功能清单或实现说明。开源版只用于验证想法，**不得**作为本产品的交互、范围或架构参考。  
> **读者**：线上版研发、设计、以及需要向投资人讲清「我们在做什么」的团队成员。  
> **版本**：2026-08-18 · 草案

---

## 0. 先把两件事分开

| | 开源实验版 | 本产品（托管上线版） |
|---|---|---|
| 给谁 | 开发者、愿意自建的人 | 要学习的人 |
| 谁提供算力与解析 | 用户自己配模型和解析 | **我们提供** |
| 账号 | 本机单用户即可 | 多用户、数据隔离 |
| 功能密度 | 允许实验、允许失败 | 只保留能完成「提升」的闭环 |
| 成功标准 | 想法能跑、能看过程 | 打开就能学、愿意每天回来 |

投资人听的是右边这一列。开发排期也只认右边这一列。实验里验证成功的能力，经过本文件改写后才能进线上；未改写的，默认不进。

## 1. 产品是什么

**一句话**：把用户自己的学习资料，变成每天可以刷、卡住可以问、问的时候能翻到书上原句的私人练习。

**不是**：通用聊天机器人、第二大脑、笔记软件、公开题库网站、知识图谱展示台。

用户付的是时间（以及将来可能的订阅）。换到的是：对着**自己正在学的那本书/讲义**练习，而不是对着网上一套无关的题。

### 1.1 为什么现在有人会要

- 资料已经数字化（PDF、课件、拍的书页），但「看过」和「会了」之间缺练习。
- 通用 AI 可以讲题，但讲的不是**这一页、这一版教材**；搜题软件有题，但不是用户这本书里的叙述和例题。
- 中学生、大学生、自考/考证的人，真正缺的是：**就着我正在看的材料，今天练几道，不会了有人按书讲。**

### 1.2 和常见替代品的差别（对外可直接说）

| 替代 | 他们做的 | 我们做的 |
|---|---|---|
| ChatGPT / 通用对话 | 什么都能问 | 只围着用户的书练和讲，答案能指回原文 |
| 作业帮 / 题库 App | 海量公共题 | 题从用户自己的资料来，先保证「像这本书」 |
| ChatPDF | 问文档 | 问完要能**做题**；做题卡住再问，并打开那一页 |
| Anki | 用户自己制卡 | 系统从资料出题，用户负责做和问 |

护城河不在「我们有 Agent」，而在：**资料 → 题（可去重、可溯源到章节）→ 练习记录 → 按掌握度再练**。题和掌握度都绑在用户自己的书上，越用越贴他。

## 2. 给谁用

### 2.1 首要用户（上线只服务这一类）

**正在用一份或几份材料推进一门课/一个考的人。**

典型：大学专业课教材、高中教辅、考证讲义、老师发的 PDF。他们已经有材料，缺的是练习和针对材料的讲解。

使用约束（产品必须承认）：

- 时间碎，单次 10–20 分钟。
- 不想配置任何模型和解析。
- 手机或电脑打开就能继续昨天那本书。

### 2.2 明确暂缓的用户

- 想做「人生第二大脑」、什么都往里扔的人（生活区可以以后再做，不进首发）。
- 没有材料、只想刷公共题的人（那是题库产品，不是我们）。
- 需要学校/班级管理后台的机构（可以是下一轮故事，不是首发）。

### 2.3 用户能感知的结果

一周后他应该能说出：

1. 我的书在软件里，不是在网盘里吃灰。  
2. 我今天对着书练了几道。  
3. 不会的时候，讲解是按书上的话说的，并能翻到那一页。

说不出这三句，产品就还没做成。

## 3. 核心循环（唯一主路径）

产品只优化这一条，其它入口都为它让路。

```
打开 → 看到「今天可以学的书」
     → 上传（若还没有）或继续已有的书
     → 等待：解析 / 出题（我们做，用户只看到进度）
     → 开始练习（默认今天这一组，不必自己组卷）
     → 每一题：会做 / 做错 / 我不会
     → 错或不会：解析 + 原文 +「和我讲讲这一页」
     → 结束：一句人话总结（今天练了什么、下次从哪继续）
```

**原则**：用户决策不超过两步。「今天学哪本」和「开始」。出几道、出哪些页、Agent 怎么跑，默认系统决定；进阶设置可以藏，但不能挡路。

### 3.1 三态答题（必须做对的交互）

每一题只有三种结束方式，界面权重相同：

| 状态 | 用户动作 | 系统立刻做的事 |
|---|---|---|
| 会 | 提交且正确 | 短反馈，下一题。不堆原文。 |
| 做错 | 提交且错误 | **主区域**展示解析 + 本题依据的原文片段；可「打开这一页」。 |
| 我不会 | 主动点「不会」 | 不判对错；主区域进入辅导：结合**本题绑定的章节/页**提问式讲解，引导他自己说出来。 |

「我不会」不是弱者通道，是一等公民。这是和「对了下一题、错了下一题」的题库产品最大的产品差异，必须做满，不能塞进侧栏。

### 3.2 出题在产品里长什么样（用户侧）

用户**不**需要理解 Agent、工具、并行、思考过程。

用户只看到：

- 这本书正在准备练习（进度：解析中 / 出题中 / 可以学了）。
- 准备好之后：「开始今天的练习」或「已有 N 题可刷」。

失败时：人话原因 + 可重试，不要日志。后台可以记详细过程，产品界面不展示实验版那种过程监视。

出题策略（产品规则，不是实现细节）：

1. **优先提取书中已有例题、习题**，题干、图、公式尽量保持原样。  
2. 再按该页/该节知识点**少量补题**，补题必须能指出依据的原文。  
3. 宁可少、贴书，不可多、像另一本参考书。  
4. 题绑定：文档 + 页或章节 + 知识点标签。标签是给人看的短名（「定积分」），不是技术字符串。  
5. 同一份材料（内容哈希相同）在全站只解析、出题一次，其他用户获得引用；各人的答题记录隔离。

题型以选择、填空、简答、应用为主。复杂交互（填图、拖拽）仅当书页本身就是这类题、且体验稳定后，作为后续能力，**不进首发承诺**。

## 4. 信息架构（上线要少）

首发只保留用户能理解的四件事：

| 导航名 | 作用 | 打开默认看到 |
|---|---|---|
| 今天 | 回家。继续上次的书，或开始今天的练习 | 进行中的书、可学状态、一颗主按钮 |
| 书架 | 我的学习资料 | 学习区文档列表；上传；每本书的「可学 / 准备中」 |
| 练习 | 刷题与「不会」辅导 | 选书后直接进题；不要先经过「出题工作台」 |
| 我的 | 账号、已学摘要 | 简单统计：练了多少、哪些知识点还不稳 |

**首发不要单独做的入口**（即使实验版有）：出题控制台、解析实验室、通用全库聊天、计划/日程、成就墙、第二大脑/生活区、知识图谱首页。这些或合并进上述四处，或以后再开。

通用「和 AI 聊任何事」若要保留，只能从「这本书」里进入（「问这本书」），默认带本书上下文和引用，**禁止**作为与练习平级的一级导航。

## 5. 关键页面规格

### 5.1 今天（首页）

- 若无书：只强调一件事——「把正在学的材料加进来」（上传 PDF / 图片）。一句说明：我们会做成可以练习的内容。  
- 若有书但还不能练：该书进度（准备中），不提供空的「开始刷题」。  
- 若可练：主按钮「继续《书名》」。次要：「换一本」。  
- 没有快捷入口迷宫，没有实验开关。

### 5.2 上传与准备

- 上传后立即回到该书卡片，状态为「正在准备」。  
- 准备包含解析与出题，对用户是一段等待，不是两个要他操作的工种。  
- 时长用诚实预期（例如「通常几分钟到十几分钟，页数多会更久」），可离开，回来仍是这本书。  
- 成功：状态变为可学，并提示题量级（「已准备约 N 道练习」）。  
- 失败：能重试；敏感/损坏文件用人话说明。

### 5.3 练习页

- 顶部：书名、进度（第 x / n 题），不要技术状态。  
- 中部：题干（公式、书中原图必须能显示）。  
- 下部：作答 + 三个收尾动作（提交 / 不会 / 跳过若需要则弱化）。  
- 提交后反馈占主栏，原文卡片在解析下面，不在右栏独家出现。  
- 「和我讲讲」在不会/答错后出现，进入的是本题辅导，不是新开一个空白聊天。

### 5.4 辅导（绑题、绑页）

- 上下文 = 本题 + 绑定页/节原文（可截断，但必须是对的那一段）。  
- Agent 角色：助教，用提问把人领到答案附近，而不是直接替他写完。  
- 回复中的依据要带引用；点击打开该书该页并尽可能高亮。  
- 辅导结束可「回到下一题」，不要把人丢在对话里找不到练习。

### 5.5 书架中的一本书

一本书详情只回答：

- 能不能练、有多少题、我练得怎样（粗：已练 / 正确趋势 / 不稳的知识点几个词）。  
- 开始练习。  
- 需要时：按章节练（进阶）。默认仍是「系统出一组今天的题」。

不展示：Agent 列表、工具调用、并发路数、原始日志。

## 6. 功能分层

### 6.1 首发必须有（没有则不算上线）

1. 注册/登录，用户数据隔离。  
2. 上传学习资料（PDF 为主，图片为辅）。  
3. 我们侧完成解析与出题，用户只看进度。  
4. 按书练习；三态答题；错题/不会展示解析与原文。  
5. 针对本题、本页的辅导。  
6. 引用可打开到原文位置。  
7. 公式与书中插图在题干/解析中可见。  
8. 同一材料全站去重，个人答题记录分开。

### 6.2 首发可以弱、但要有口子

- 按章节出练习（默认自动即可）。  
- 「问这本书」（带引用的阅读问答）。  
- 极简的掌握情况（几个知识点弱，不是仪表盘展览）。

### 6.3 明确首发不做

- 用户自备模型/解析、任何「连接服务器 / 填 API Key」。  
- 让用户配置出题并行、看思考过程、当运维。  
- 生活区、计划提醒、成就、公开社区、班级后台。  
- 为演示而做的复杂题型（拖拽填图等），除非该体验已在实验中稳定且有真实书页需求。  
- 把通用聊天当首页。

### 6.4 上线后（有真实使用再做）

- 按薄弱知识点自动组「今天这几题」（间隔练习）。  
- 多人引用同一本书时的题质量投票/纠错（仍是我们的题，不是 UGC 社区）。  
- 学校/班级若有明确付费对象再单独立项。

## 7. 服务与账号（产品承诺）

用户买到或注册到的是**服务**，不是软件安装包。

我们负责：

- 账号与同步（换设备能继续那本书）。  
- 文件存储、解析、出题所用的模型与额度。  
- 内容安全与基础审核（违法资料拒绝）。  
- 隐私：用户的书和答题默认仅自己可见；去重哈希不得导致 A 能看见 B 的笔记或成绩。

用户负责：

- 保证有权使用所上传的材料（个人学习用途）。  
- 按套餐使用（具体计价不在本设计展开，产品上要能展示「本月还可准备几份书 / 还可练多少」这类限额，避免突然失败）。

**加载与等待**：解析和出题是长任务，产品要按「可离开的工作」设计，不能做成必须盯着的控制台。

## 8. 数据与对象（产品对象，不是表结构）

只要求研发理解这些对象及其关系：

```
用户
  └─ 书架上的「书」（对一份材料的引用）
        ├─ 材料本体（全站可去重）
        ├─ 结构：页 / 章节（用于打开原文和绑定题）
        ├─ 题（全站可去重；带来源页、标签、解析）
        └─ 该用户的练习记录（不可与他人合并）
```

标签：给人和辅导用的知识点名。来源可以是目录、章节标题、模型抽取，但展示必须是干净中文名。错误标签等于错误产品。

出题与练习失败不能污染别人的同一本书：去重只共享「材料与题」，不共享「谁不会」。

---

## 9. Agent 在产品中的角色

Agent 是实现手段，不是产品卖点名称。对外可以说「针对你的书出题和讲解」，不要把「多 Agent、工具循环」讲成用户利益。

产品规则：

- **出题 Agent**：在服务端跑完；用户只消费结果与进度。  
- **辅导 Agent**：只在「这题 / 这页」场景出现，有边界，有引用。  
- **禁止**：让用户围观或配置 Agent。那是实验版的事。

质量底线：题必须能指出依据；辅导必须能打开依据。做不到就视为该题不合格，宁可不出。

## 10. 体验原则（给设计和前端的验收语言）

1. **主路径不超过两个选择。**  
2. **等待可离开。** 回来状态还在。  
3. **错与不会占主视觉。** 原文不藏侧栏。  
4. **所有学习对话都有书的位置。** 没有位置的回复不算完成。  
5. **少即是好。** 增加一个一级入口，必须删掉或合并另一个。  
6. **像书，不像控制台。** 字体、密度、颜色为阅读和做题服务。  
7. **移动端能完成练习和不会。** 上传可以电脑优先，但练习不能只在宽屏可用。

## 11. 成功怎么衡量

首发三个月，只盯能说明「提升闭环成立」的数：

| 指标 | 含义 | 差的信号 |
|---|---|---|
| 上传后 24h 内开始第一次练习的比例 | 准备流程有没有劝退 | 大量停在「准备中」或找不到入口 |
| 单次练习完成至少 5 题的比例 | 练习本身能不能做完 | 题看不懂、公式图挂了、交互断 |
| 「不会」或答错后打开原文/辅导的比例 | 差异化体验有没有被用到 | 功能在但没人点，或点了没用 |
| 7 日内第二次打开同一本书的比例 | 有没有理由回来 | 一次性 AI 玩具 |

不把 DAU 游戏化、成就数、聊天轮次当核心指标。

## 12. 和开源实验如何同步（给两边团队的协议）

1. 实验版可以乱，线上版以本文为准。  
2. 实验验证了某能力（例如某种题型、某种出题策略），要进线上，必须先改写本节对应的用户可见行为，再排期；禁止「把仓库功能迁过去」。  
3. 线上出现的产品问题，用本文的循环和原则改；不要到实验仓里找对照实现当设计。  
4. 本文未写的能力，默认不上线。

## 13. 给投资人的一页（可单独抽出）

**问题**：学生手里已经有教材和课件，但「看过」变不成「会了」。现有工具要么是别人的题，要么是不着书的聊天。

**产品**：知拾把用户自己的材料做成可练习的内容。系统出题、用户做题；做错或不会时，按这本书的原文讲，并能翻到那一页。服务由我们托管，用户不用配置。

**为什么是我们**：材料、题、讲解、掌握情况绑在同一本书上，越用越个人；同一份教材全站出题一次、人人可练、记录分开，有规模效应。

**现在做到哪**：闭环能力已在内部版本验证；上线版要做的是多用户服务、去掉实验界面、把「今天打开就能练」做成唯一路径。

**不讲**：模型名叫什么、开源仓库有多少功能、Agent 内部有几路并行。

## 14. 线上研发的下一步（产品顺序，不是技术任务）

1. 按第 4 节收导航：今天 / 书架 / 练习 / 我的。  
2. 按第 5.3–5.4 节做满三态答题与绑页辅导（这是产品差异，先于任何新功能）。  
3. 上传到可练的等待体验（第 5.2），作为服务承诺的一部分。  
4. 公式、原图、引用跳转作为发布门槛，不是优化项。  
5. 用第 11 节指标做一版可统计的埋点，再谈下一轮功能。

完成 1–4，才有和投资人演示的「打开就能学」。在此之前加入口、加实验功能，都算偏离本设计。
